# 链表

课程：数据结构
知识点：链表

来源：码上知新课程知识库

## 核心概念

单链表结点保存数据及后继指针 next，尾结点的 next 为空。访问第 k 个结点需要沿链遍历，通常为 O(k)；若已知前驱，在其后插入或删除一个结点只需常数次指针修改。
插入结点 s 到 p 后面，应先 s->next=p->next，再 p->next=s。逆序修改会丢失原后继或构造自环。
删除 p 后面的 q 时，先保存或连接 q 的后继，再释放 q。new 创建的独立结点用 delete 释放，释放后不能再读取 q->next。
若要删除头结点，必须更新头指针；哨兵结点可以统一边界处理，但需明确哨兵本身是否计入有效元素。

双链表结点同时保存 prev 与 next，可向前和向后移动。已知要删除的结点 q 时，要更新它前驱的 next 和后继的 prev；若 q 是首尾结点，还要更新 head 或 tail。带头尾哨兵的设计可减少边界分支，但哨兵不是用户数据，不能当普通元素释放或计数。单链表若只知道待删除结点却不知道前驱，一般仍需寻找前驱；不能把某些复制后继数据的技巧推广到尾结点、不可复制数据或保持结点身份的场景。

## 代码示例

下面示例使用 C++17，可独立保存为 .cpp 文件编译运行。assert 检查关键结果；阅读时先预测输出状态，再运行验证。

```cpp
#include <cassert>
struct Node { int value; Node* next; };
int main() {
    Node* head = new Node{1, nullptr};
    Node* s = new Node{2, nullptr};
    s->next = head->next;
    head->next = s;
    assert(head->next->value == 2);
    Node* q = head->next;
    head->next = q->next;
    delete q;
    assert(head->next == nullptr);
    delete head;
    head = nullptr;
}
```

## 常见错误

在检查指针是否为空之前访问成员；释放结点后读取 next；只把局部指针设为 nullptr 却没有连接前驱和后继；误认为链表的任意位置访问都是 O(1)。
上例用于展示指针连接顺序，实际工程应结合智能指针或标准容器管理异常路径上的资源。

实现双链表时只更新一个方向会让正向遍历看似正确、反向遍历却失效。插入和删除前应确认结点属于该链表，避免把两个链表错误连接；循环链表的终止条件不同于空指针结尾的链表。遍历删除多个结点时，先保存下一结点再释放当前结点。复制含裸指针的链表对象若只复制头指针会导致共享结点和重复释放，应明确深复制、移动或禁用复制策略。

## 易错题分析

题116：先连接新结点的 next，再修改前驱的 next。
题117：链表按序访问，不能用地址二分实现下标访问。
题118：p->next=q->next 必须在 delete q 前执行。

删除单链表结点时先问是否已知前驱，再判断是不是头结点；有前驱则重连 next，没有前驱且删除头部则更新 head。删除双链表结点时用四个箭头检查前后连接，最后才释放内存。空链表、单结点链表、删除首结点和末结点是必须验证的边界。分析时间复杂度时，把寻找结点的 O(n) 与已知位置后修改指针的 O(1) 分开，不要因为代码只有几行就忽略此前的查找成本。
