# 类与对象、继承与多态

课程：C++
知识点：类与对象、继承与多态

来源：码上知新课程知识库

## 核心概念

类封装数据和操作。class 成员默认 private，struct 成员默认 public。构造函数负责对象初始化，没有返回类型；建议用成员初始化列表初始化数据成员。
const 成员函数不能通过 this 修改非 mutable 的非静态数据成员。局部变量仍可修改，mutable 成员用于需要在逻辑常量操作中更新的内部状态。
基类虚函数允许通过基类指针或引用动态派发到派生类的重写实现。override 让编译器检查重写关系，能发现参数类型或 const 限定不匹配。
若允许通过基类指针 delete 派生类对象，基类应具有可访问的虚析构函数。非虚析构的普通基类不适合用于这种多态删除。

继承表达类型之间的关系，公有继承允许派生对象在适当场景作为基类使用。构造顺序是先基类、再按声明顺序初始化成员、最后进入派生类构造函数体，析构通常反向进行。虚函数的运行时多态体现为同一个基类接口对不同实际对象产生不同实现；编译器常通过虚函数表等机制实现，但 C++ 标准不要求特定内存布局。抽象类含有纯虚函数，不能直接实例化，派生类需要提供所需实现才能成为具体类型。

## 代码示例

下面示例使用 C++17，可独立保存为 .cpp 文件编译运行。assert 检查关键结果；阅读时先预测输出状态，再运行验证。

```cpp
#include <cassert>
#include <memory>
class Shape {
public:
    virtual int area() const = 0;
    virtual ~Shape() = default;
};
class Square : public Shape {
    int side;
public:
    explicit Square(int n) : side(n) {}
    int area() const override { return side * side; }
};
int main() {
    std::unique_ptr<Shape> shape = std::make_unique<Square>(3);
    assert(shape->area() == 9);
} // 通过虚析构正确销毁派生对象
```

## 常见错误

把构造函数写成带返回类型的普通函数；把重写误写为不同签名的新函数；按值传递基类造成对象切片；以为所有成员函数都会自动动态派发。
上例假设边长为小正整数，生产代码应检查输入和乘法溢出。

常见错误还包括把成员初始化列表的书写顺序当成实际初始化顺序；在构造函数内依赖尚未初始化的成员；按值存储基类导致派生部分被切掉。构造和析构期间的虚调用不会动态派发到尚未构造或已经析构的更派生部分。基类析构是否需要 virtual 要结合使用方式判断，尤其关注是否经由基类指针删除。不要通过强制类型转换掩盖错误继承关系或不匹配的函数签名。

## 易错题分析

题203：多态删除关注虚析构函数。
题208、209：动态派发依赖虚函数；override 用于编译期检查，不会使普通函数自动成为合法重写。
题225—227：class 默认 private；构造函数初始化对象；const 成员函数不能直接修改普通数据成员。

分析多态输出题时分清指针或引用的静态类型与对象的动态类型：非虚函数按静态绑定规则选择，虚函数经由基类指针或引用调用时按实际对象选择最终重写。再检查是否发生对象切片、函数隐藏或 const 限定差异。分析对象生命周期时，按基类、成员、派生类的顺序列出构造，再反向列出析构。对资源管理题要追踪最终执行哪个析构函数，不能只看是否写了 delete。
