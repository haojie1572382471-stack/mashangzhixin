# 比赛交付准备与演示脚本

本文件是交付工作稿，不代表已制作视频、PDF或已完成报名。规则依据为团队提供的比赛文本，最终以组委会最新公告为准。

## 作品定位与可验证创新

面向C++和数据结构初学者，把一道错题连接到有来源的讲解、复习步骤和另一道验证题。主要价值在“看见错误—理解可能误区—验证迁移”，避免只收藏答案不复习。

可展示的技术点：服务端真实作答驱动推荐；知识资料约束的题后辅导；按不同题覆盖估计掌握度，保留首次表现；无模型环境下仍能练习和查看资料；幂等保存避免网络重试重复计分。不要宣称发明了新的机器学习算法、拥有向量数据库或自主Agent。

## 建议的7分钟演示

| 时间 | 画面与讲解 |
| --- | --- |
| 0:00—0:40 | 痛点：收藏错题但不知道错在哪里，复习缺少验证。介绍目标学生与两门课程。 |
| 0:40—1:30 | 注册/登录；开始学习；答错一道题；展示标准答案与解析。 |
| 1:30—2:40 | 点击针对性辅导，解释模型依据真实选择与课程资料给出“可能误区”；展示来源与换一道题验证。 |
| 2:40—3:30 | 查看真实学习进度、首次正确率、覆盖题数；展示薄弱题靠前和同题不刷高掌握状态。 |
| 3:30—4:15 | 加入错题、查看与复习；切换账号证明错题和进度隔离。 |
| 4:15—5:10 | 课程答疑、资料来源；解释关键词检索和资料不足时拒答。 |
| 5:10—6:00 | 使用预先准备的无密钥演示实例，展示本地资料和题库解析兜底；明确不是AI生成。 |
| 6:00—7:00 | 架构图、回归评测结果、团队分工、当前局限与后续真实用户试用。 |

视频应按规则制作5—8分钟、1080p或以上MP4，普通话讲解。不要录入密钥、账号文件或私人学习数据。在线模型演示前先测试余额与网络；不要剪辑伪装实时生成。

## 技术PDF提纲（建议18—24页，不超过30页）

1. 封面与团队信息；2. 用户需求与使用场景；3. 功能结构；4. 系统架构；5. 前端文件和状态设计；6. 登录与数据隔离；7. 学习记录持久化和幂等；8. 掌握度与推荐规则；9. RAG切块和检索；10. 模型选型、Prompt约束与回退；11. 错因辅导与验证练习；12. 用户体验；13. 测试与RAG回归结果；14. 部署指南；15. 创新点及局限；16. 分工、总结与展望。

目前的检索回归集参与过调试，必须标为回归结果。队友应准备独立问题集并记录失败案例，再补充真实试用反馈；未开展前不得填写用户数量或效果提升百分比。

## 两人分工

主要开发者负责代码、接口、身份鉴权、模型流程、测试脚本和运行包。另一位成员负责独立题目核对、资料来源审校、按步骤操作回归、记录截图与问题、演示讲稿和文档排版。两人都需要能解释核心闭环、数据来源、回退机制及实现边界。
